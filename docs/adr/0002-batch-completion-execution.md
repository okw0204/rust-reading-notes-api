# 一冊を原子的に保存し、冊子間は親 Future の中で並行に進める

一括読了記録は、一冊の中では読了への状態変更とメモ追加を同時に成立させ、複数冊の間では独立した結果を返す。一冊ごとの処理を既存の `BookRepository` Seam の背後で原子的に保存し、service の親 Future が最大 8 件の子 Future を所有して並行に進める。切り離した background task は作らない。

## 保存単位と失敗

一冊の処理では、現在状態が読書中であることを条件にした状態更新とメモ追加を同じトランザクションで実行する。両方が成功して commit したときだけ読了結果を成功とする。

| 失敗 | 読了結果 | その一冊の保存状態 |
| --- | --- | --- |
| 本が最初から存在しない | `not_found` | 変更なし |
| 取得した本が未読または読了 | `conflict` | 変更なし |
| 取得後に状態が変わった、または削除された | `conflict` | 変更なし |
| 状態更新後、メモ追加または commit が失敗した | `internal_error` | トランザクションを rollback し、どちらも変更なし |
| 保存値をドメイン型へ復元できない | `internal_error` | 変更なし |

冊子間を一つのトランザクションにはしない。ある一冊が失敗しても、ほかの一冊の進行を中止せず、確定済みの保存を取り消さない。したがって一括読了記録は部分成功を許す。入力規則の失敗だけは処理開始前に要求全体を拒否する。

全冊を一つのトランザクションにする案は、全体成功・全体失敗が業務上必要なら成立する。しかし冊子間は独立しており、一冊の競合で別の本の読了を失わせる理由がない。また単一トランザクションは独立した Future の進行と部分成功を扱う学習目標に合わない。状態更新とメモ追加を別々に確定する案は、読了だけが残る状態またはメモだけが残る状態を許すため採用しない。

## Interface と Adapter

一冊の読了記録に必要な原子的保存は、既存の `BookRepository` Interface に一つの操作として加える。service が `update_book_status` と `insert_note` を順に呼び、rollback の責任まで持つ形にはしない。トランザクションと条件付き更新を SQLite Adapter の内部へ閉じ込め、フェイクも同じ「両方が残るか、どちらも残らないか」という契約を満たす。

新しい production Seam は作らない。SQLite とメモリ上のフェイクという実在する二つの Adapter がすでに差し替わるためである。並行性や失敗注入を制御する機能はフェイクの実装に置き、production の Interface にテスト専用の待機操作を加えない。

service は取得した `StoredBook` を読書中として検査し、`Book<Reading>` を消費して `Book<Finished>` を作ってから原子的保存を依頼する。これにより、ドメインの遷移判断は service、DB の現在状態と複数 SQL の確定は Adapter という責任を保つ。

service がトランザクションを直接扱う案は、保存技術をユースケースへ漏らし、フェイクと SQLite で異なる Interface を必要とするため採用しない。読了記録専用の repository trait を追加する案も、既存の本とメモの保存先が同じで Adapter も同じため、Seam を増やす根拠がない。

## 並行に進める範囲

各入力は、一冊の処理の中では次の順序を守る。

1. 本を取得する。
2. 読書状態を検査し、読書中の本を読了へ遷移させる。
3. 読了への変更とメモを原子的に保存する。
4. 保存済みの値から読了結果を作る。

異なる `book_id` の処理には順序関係がない。要求全体の検証後、親 Future は一件目の完了を待ってから二件目を始めるのではなく、すべての子 Future を進行可能にする。Adapter が接続や書き込みを直列化することはあり得るが、service が不要な逐次待機を加えないことを Interface の一部とする。

入力順と完了順は分ける。各子 Future は入力位置と検証済みの入力を所有し、完了時に位置と読了結果を返す。親 Future は全結果を集め、入力位置の順に並べて返す。`book_id` の重複を禁止するため、同じ本に対する冊子間の順序規則は不要である。

逐次実行は同じ保存結果を作れるが、独立した I/O の待機中にほかの本を進めるという性能上の Interface を満たさない。完了順のまま返す案は集約処理を単純にできるが、利用者が入力との対応を位置で追えず、呼ぶたびに順序が変わり得るため採用しない。

## 所有権と処理の寿命

handler の Future は要求と共有された service を保持し、service の親 Future をその場で待つ。親 Future は検証済みの入力、入力位置、すべての子 Future を所有する。子 Future は一冊分の入力を所有し、共有可能な repository を必要な期間だけ借用する。

子 Future は親から切り離さない。この形なら、並行に進めるためだけに入力を `Arc` へ包んだり、`'static` にしたりする必要がない。repository への複数の共有借用を同時に進めるため、repository と返される Future には既存どおり `Sync` と `Send` の条件が必要になる。

親 Future が完了する前に破棄された場合、未完了の子 Future も破棄され、それ以上は進めない。すでに commit した一冊の結果は保存先に残る。commit 前の一冊はトランザクション単位で rollback され、状態変更とメモの片方だけを残さない。どの冊数まで commit 済みかは終了時点に依存し、型だけからは決まらない。HTTP 応答は返らないため、利用者が必要なら既存の詳細取得で保存状態を確認する。

切り離した task を使う案は、handler の終了後も処理を完了させる要件がある場合には成立する。しかし今回は task の所有者、再取得可能な処理状態、shutdown、再試行を追加しないまま background 実行だけを導入すると、HTTP 応答と保存結果の関係が曖昧になるため採用しない。

## 同時に進める仕事量

一要求を 8 件以下に制限し、その範囲では全件を並行に進める。別の semaphore や worker queue は導入しない。要求数の上限がそのまま一つの親 Future が所有する子 Future 数の上限となり、無制限の仕事生成を防ぐ。

8 という上限は業務上の恒久的な最大値ではなく、教材で全件を見通せる小さい要求と、複数件の並行性を両立させる Interface 上の制約である。より大きい一括処理、要求をまたぐ公平性、DB 接続数との厳密な連動が必要になった場合は、ページ分割、明示的な並行数制御、queue を検討する。

## 型で保証することと実行時に保証すること

| 対象 | 型で表すこと | 実行時に確かめること |
| --- | --- | --- |
| メモ | `NoteBody` が検証済みの空でない本文である | 要求全体を保存前に検証し終えたか |
| 状態遷移 | `Book<Reading>` だけが `Book<Finished>` を作れる | DB の現在状態が取得時と同じ読書中か |
| 保存 | 原子的保存操作の入力と成功値 | SQLite の transaction が両方を commit または rollback したか |
| 入力との対応 | 子 Future が入力位置を所有する | 結果を完了順ではなく入力順へ戻したか |
| 資源上限 | 上限以内として構築した入力の表現 | 件数、重複、Adapter が実際に利用できる接続やロック |
| 終了 | 親 Future が子 Future を所有する構造 | 破棄時点でどの一冊が commit 済みか |

## 決定的な検証

- Router と実 SQLite から、全件成功、入力不正、未検出、状態競合、混在した部分成功を確認し、詳細取得で保存状態を再取得する。
- SQLite Adapter から、状態変更後のメモ保存失敗を注入し、transaction が片方だけを残さないことを確認する。
- 既存の repository Seam のフェイクに制御可能な待機点を置き、少なくとも二つの子 Future が開始済みになるまでどちらも解放しないことで並行進行を確認する。実時間の短さや偶然の順序は使わない。
- 同じフェイクで一件だけを失敗させ、ほかの Future が継続すること、完了順を変えても応答が入力順であることを確認する。
- 親 Future を制御可能な待機中に破棄し、未完了処理が継続せず、確定済みの結果だけが残ることを確認する。

有限の検証は観測した経路の契約を示すが、任意の scheduler、任意の障害、任意の終了時点を網羅しない。型検査は Future の所有関係や `Send` などの条件を示せるが、実際に並行して poll されたことや保存結果は示さない。
