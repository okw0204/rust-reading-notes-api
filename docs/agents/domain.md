# Domain docs

Engineering skill がコードベースを探索するときに、このリポジトリのドメイン文書を参照するための規則を定める。

## 探索前に読む文書

- リポジトリルートの `CONTEXT.md`
- `docs/adr/` のうち、作業対象に関係する ADR

これらが存在しない場合は、そのまま作業を続ける。不在を問題として報告したり、事前作成を提案したりしない。用語や意思決定が実際に確定したときに、`/domain-modeling` skill が必要な文書を作成する。

## ファイル構成

このリポジトリは single-context 構成とする。

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

## 用語集の語彙を使う

Issue のタイトル、リファクタリング案、仮説、テスト名などでドメイン概念を表す場合は、`CONTEXT.md` で定義された用語を使う。用語集が避けている同義語へ言い換えない。

必要な概念が用語集にない場合は、プロジェクトで使われていない言葉を新たに作ろうとしていないか見直す。実際に用語集の不足であれば、`/domain-modeling` で扱う事項として記録する。

## ADR との矛盾を明示する
